# Численные пороги

В `main.cpp` включена ловушка `FE_UNDERFLOW`. В запуске
`./a.out 1000 18 10 1` остатки округления постепенно уменьшались до
произведения порядка `4.49e-330`, вызывавшего остановку программы.
После удаления зануления из функций умножения запуск `1000 18 0 1`
снова аварийно завершался с включённой ловушкой. В диагностической
копии без ловушек был подтверждён флаг `FE_UNDERFLOW`.
Теперь отдельная очистка нормированной ведущей строки и исключаемого
блочного столбца устраняет это падение: получены
`Res1≈4.71e-16`, `Res2≈1.51e-11`. В основной программе ловушка сохранена.

Все матрицы обрабатываются одним блочным алгоритмом в `double`.
Нормировка ведущей строки выполняется умножением на обратный ведущий
блок. Отдельные функции прямой нормировки и расчёта порога удалены:
оценки вычисляются в существующих функциях. `calculate_block_norm`
принимает начальный индекс оставшейся части блока.

Порог отказа фиксируется относительно нормы исходной системы:
`pivot_eps = n * DBL_EPSILON * ||A_исходная||_inf`.
Ведущий элемент с модулем `<= pivot_eps` отклоняется при обращении
кандидатов и решении последнего неполного блока. Порог не уменьшается
вместе с оставшейся частью матрицы, в том числе при `m=1`.
Общее масштабирование матрицы масштабирует порог в той же пропорции.
Это критерий численной вырожденности по ведущим элементам, а не полная
оценка числа обусловленности и не гарантия точности принятого решения.

Порог зануления вычисляется отдельно перед каждым скалярным шагом:
`eps = DBL_EPSILON * ||оставшаяся часть блока||_inf`.
Результаты обновления элементов самого блока с модулем `<= eps` обнуляются.

Обе функции умножения, `matrix_multiplication` и
`matrix_multiplication_subtract`, записывают вычисленные значения
без порога зануления. Параметр `eps` и его вычисление для этих вызовов удалены.
Перед обновлением нижних блоков выполняются отдельные проходы очистки:
после нормировки ведущей строки для коэффициентов справа от диагонального
блока применяется `DBL_EPSILON² * max(1, max|строка|)`;
для исключаемого блочного столбца — `DBL_EPSILON² * ||A_исходная||_inf`.
Они удаляют очень малые остатки округления. Одна очистка только строки или
только столбца не устранила падение в контрольном случае.
RHS не обрезается. Дополнительная работа по всему решению имеет порядок
`O(n²)`; проверки не добавляются внутрь ядер умножения.
При общем масштабировании входной системы порог столбца масштабируется
вместе с ней, а нормированная ведущая строка сохраняет свой масштаб.
Для малых коэффициентов исключения и обратного хода сохраняются
проверки относительно ведущего элемента.
Обычное суммирование, рабочий тип `double`, строгая арифметика и ловушки
сохранены. Компенсированное суммирование и итерационное уточнение не добавлены.

Отсечение малых элементов является численной аппроксимацией;
для плохо обусловленных матриц точность нужно оценивать по невязкам.
Этот способ устраняет воспроизведённые цепочки малых остатков, но не гарантирует
отсутствие underflow для любых возможных входных значений `double`.

Сравнение трёх чередующихся запусков на `n=3000` показало уменьшение медианы
`T1` на 3–10% при совместной очистке; напечатанные невязки совпали с исходной
версией. Прямая нормировка ведущей строки скалярными исключениями улучшила
точность, но для `m=18,64` увеличила время примерно на 1–5%.
Для одного блока `n=m=1500` прямая нормировка с пропуском ненужного обращения
оказалась быстрее примерно на 33%.
Подробности и исходные замеры сохранены в
[сравнении вариантов](build/underflow-comparison-h4yb79lt/README.md).
В исходной версии для замеров отключалась только ловушка underflow;
проверяемые варианты запускались со всеми ловушками.

Проверка из корня репозитория:

```bash
make -C task_3 a.out
./task_3/a.out 5000 64 1 1
./task_3/a.out 1000 18 10 1
```

Регрессии для новых файлов и общего масштабирования:

```bash
python3 -B -m unittest discover -s task_3/tests -p test_solver.py -v
```

Проверяются 46 сочетаний файлов `a`, `a20`, `a40`, `b`, `c`, `d`, `e`, `f`
с блоками `1..n+1` и 20 вариантов масштабирования `a` и `b`.
`a20.txt` и `a40.txt` должны решаться; `b.txt` и `f.txt` должны давать
`Res1 = Res2 = -1`. Маленькая обратимая матрица `tiny_diagonal_5`
в стандартном наборе также должна решаться.

При `n=12`, `s=4`, `m=1..12` допускается численный отказ
`Res1 = Res2 = -1`; при успехе проверяются конечные неотрицательные
невязки как диагностические значения. Те же матрицы записываются
в файлы с точным сохранением значений `double`; результаты формулы
и файлов должны совпадать. Погрешность решения `Res2` остаётся
диагностикой: малая невязка не гарантирует точного восстановления решения.
Дополнительно проверяется решение при `n=5` и численный отказ при `n=20`
для всех размеров блока `1..n+1`, формулы и файлов, а также масштабов
`1e-20`, `1`, `1e40`. Отказ сохраняет формат отчёта `Res1 = Res2 = -1`
и существующий код завершения программы `0`.

Проверка ведущих элементов не заменяет оценку обусловленности.
При `n=12` некоторые размеры блока по-прежнему дают большие невязки:
например, при `m=11` получены `Res1≈4.13e-4`, `Res2≈266.5`.
Эти значения сохраняются как диагностика; критерий отказа сам по себе
не восстанавливает точность умножения на обратный блок.

## Сравнение способов зануления

Замеры от 09.10.2026: macOS 26.7, arm64, Apple Clang 21, исходные
флаги Makefile, включая строгую арифметику. Предыдущая версия — коммит
`79d44ac89b280e1759b612c987d7d6561dfacff7`, с отдельными проходами
`clear_small_values`. Обе версии собраны одинаково и запускались по очереди.

Для `n=6000`, `r=1`, `s=1` выполнено по три запуска каждой версии;
в таблице приведена медиана `T1` в секундах.

| m | Отдельные проходы | Зануление при записи | Уменьшение времени |
|---|---:|---:|---:|
| 18 | 20.69 | 20.25 | 2.13% |
| 32 | 19.99 | 19.55 | 2.20% |
| 64 | 14.79 | 14.53 | 1.76% |
| 128 | 11.42 | 11.41 | 0.09% |

Для каждого `m` невязки двух версий совпали во всех трёх запусках:

| m | Res1 | Res2 |
|---|---:|---:|
| 18 | 7.825459e-15 | 1.138996e-08 |
| 32 | 7.093896e-15 | 8.325756e-09 |
| 64 | 5.887379e-14 | 4.438702e-08 |
| 128 | 6.248771e-15 | 7.398109e-10 |

Отдельная проверка `5000 64 1 1`: прежняя версия — `7.95` с,
новая — `7.97` с (по одному запуску). Для `m=128` и этого случая
разница слишком мала, чтобы считать её надёжным изменением скорости.
Все 26 замеров сохранены в [zeroing_comparison.csv](zeroing_comparison.csv).

Запуск `1000 18 10 1` завершился без падения:
`Res1=1.274620e-15`, `Res2=1.197548e-11`.
Дополнительно прошли 3456 проверок двух ядер для размеров `f,k=1..8`,
`l=0..8` и порогов `0`, `0.125`, `1`: полные плитки, остатки,
значения ниже порога и на его границе.
Быстрый набор из 295 тестов проверен на обеих версиях. Первоначально
семь проверок были отмечены как `FAIL`: шесть превышений общего допуска
на матрицах Гильберта и переполнение свободных членов. Превышения допуска
на плохо обусловленных матрицах Гильберта сами по себе не означают ошибку
решателя; для `s=4` невязки теперь сохраняются как диагностические значения.

После этого добавлена проверка двух слагаемых до сложения при построении
RHS. Для конечных слагаемых одного знака проверяется
`min(abs(sum), abs(value)) > DBL_MAX - max(abs(sum), abs(value))`.
Если сумма выходит за диапазон `double`, инициализация возвращает ошибку,
не выполняя сложение. Слагаемые разных знаков не могут переполнить сумму.
Бесконечные значения также отвергаются. Режим ловушек не изменяется;
`fenv` при построении RHS не используется.
Норма матрицы проверяется до построения RHS. В суммировании модулей
для нормы также проверяются слагаемые до сложения; при выходе за диапазон
возвращается `HUGE_VAL`, который отклоняет инициализацию.
Тест `input_invalid_rhs_overflow_3` теперь проходит:
программа возвращает ошибку инициализации вместо аварийного завершения.
После исправления обработки переполнения и критериев для матриц Гильберта
быстрый набор проходит полностью: 295 из 295 проверок.

В обратном ходе `triangular_blocked_to_solution` переполнение проверяется
до умножения, прибавления к сумме и вычитания из компонента решения.
Опасная операция не выполняется: функция возвращает `false`, а `solve()` —
`-1`. Для произведения равенство с порогом `DBL_MAX / abs(x)` тоже
отклоняется, поскольку деление могло округлить порог вверх.

Чтобы не замедлять обычные матрицы, один раз вычисляется максимум модулей
матрицы, затем — максимум модулей используемого блока решения.
Если эти максимумы и текущий компонент не больше
`sqrt(DBL_MAX / (4*n))`, сумма до `n` произведений и последующее вычитание
безопасны, и используется исходный цикл без проверок каждого слагаемого.
На `5000 64 1 1` текущая версия дала `T1=7.93` с;
невязки совпали с версией без защиты обратного хода.
Дополнительно проверены 14 случаев переполнения и допустимых больших
значений, включая оба знака, неполный блок и перестановку неизвестных.

Полный набор из 535 тестов повторно запущен после защиты нормы:
аварийных завершений — 0 (до исправления — 1), прошли 533 проверки.
В двух случаях `n=4000, s=2` общий допуск `Res2 <= 1e-6` превышен:
при `m=8` получено `Res2=1.138122e-4`, при `m=32` — `4.825408e-6`.
Эти значения воспроизводятся на версии без защиты обратного хода.
Все сообщённые невязки полного набора совпали до и после защиты нормы.
Также прошли 18 граничных проверок нормы с включёнными ловушками.

# Запуск тестов

Из корня репозитория запустите **одну программу одной командой**:

```bash
bash task_3/test.sh
```

`test.sh` сам собирает `task_3/a.out` через исходный Makefile, запускает
**все 535 тестов, включая n=4000**, и добавляет
**одну строку на весь запуск** в `task_3/results_full_4000_m1_2000.csv`.
В каждой строке записываются ОС и её версия, архитектура, модель процессора
и имя компьютера, на котором выполнен запуск.
Отдельные команды сборки и запуска Python-помощников не нужны.
Makefile скрипт не изменяет. Повторный запуск
добавляет следующую строку, сохраняя предыдущие результаты. Заголовок
создаётся только один раз. При одновременных запусках запись блокируется,
чтобы строки не перемешивались.

Стандартный набор включает большие матрицы без дополнительных параметров.
Максимальный размер — `n=4000`; все случаи с `n>4000` исключены.
Размер `n=4000` проверяется для формул `s=1..3`
и размеров блока `m=8, 16, 31, 32, 64, n, n+1`. При `m=31`
проверяются неполные блоки. Для больших матриц используется `r=0`,
чтобы не печатать элементы матрицы и решения.

Сочетание `n=4000, m=1` исключено. Вместо него добавлены тесты
`n=2000, m=1` для формул `s=1..3`.

Матрицы Гильберта (`s=4`) проверяются только при `n<=15`.
Случаи `s=4, n>15` исключены из всех наборов.

Стандартный набор соответствует профилю `full`; это значение по умолчанию.
Старые результаты быстрого набора в `results.csv` сохраняются отдельно.
После замены `n=4000, m=1` на `n=2000, m=1` используется новый CSV-файл,
чтобы сохранить прежнюю историю с другим составом столбцов.
Если набор тестов изменится, скрипт попросит указать новый файл и сохранит
прежнюю историю.

**Ограничения времени нет.** Скрипт ждёт завершения каждого теста,
включая расчёты для `n=4000`. Длительное выполнение не
превращается в `-1`: это значение записывается только при отказе или ошибке.
Остановить запуск вручную можно через `Ctrl+C`; незавершённый набор
не добавляется в CSV, уже созданные логи остаются в `build/test-runs`.

Дополнительные параметры:

```bash
bash task_3/test.sh --results "task_3/results experiment.csv"
bash task_3/test.sh --profile quick
bash task_3/test.sh --no-build
bash task_3/test.sh --program /absolute/path/to/a.out
bash task_3/test.sh --help
```

Дополнительный профиль `quick` запускает 295 небольших тестов и по умолчанию
добавляет строку в `task_3/results.csv`. Обычная команда без параметров
запускает весь набор из 535 тестов. Для разных наборов нужны разные CSV-файлы.

Пути к скрипту, программе, матрицам и результатам могут содержать пробелы.
Скрипт можно запускать из любого каталога. Относительные пути в параметрах
считаются от текущего каталога; пути по умолчанию — от каталога `task_3`.
Нужны Bash, Python 3.9+, Make и C++17-компилятор. Переменная `PYTHON`
позволяет выбрать другой интерпретатор Python.

## Какие результаты записываются

Структура CSV:

```text
timestamp,system,architecture,cpu,hostname,formula_s1_n1_m1.T1,formula_s1_n1_m1.T2,...
2026-10-06T12:00:00.123456+03:00,macOS,arm64,Apple M2,computer,0.00,0.00,...
```

Сведения о системе снимаются автоматически один раз в начале запуска.
Они также сохраняются в `system.json` в каталоге логов этого запуска.
Недоступные значения обозначаются `unknown`.

Если CSV создан старой версией скрипта без сведений о системе, при следующем
запуске автоматически добавляются новые столбцы. Предыдущие времена и даты
сохраняются; для старых строк система обозначается `unknown`, потому что
её нельзя восстановить по старому файлу. Перед обновлением сохраняется
копия прежнего CSV с суффиксом `.before-system.bak`.

Для каждого теста сохраняются два времени в секундах из **последней
непустой строки stdout** программы:

- `T1` — решение системы;
- `T2` — вычисление невязок.

Внешнее время запуска процесса не используется. Итоговая строка также
проверяется на соответствие `Task`, `S`, `N`, `M` текущему тесту.

Оба времени равны `-1`, если решатель сообщает `Res1 = Res2 = -1`, процесс
завершился с ошибкой или итоговый отчёт отсутствует,
повреждён либо содержит бесконечность/NaN. Один код завершения недостаточен:
основная программа возвращает 0 и при отказе решателя.

**0.00 — допустимое успешное время.** Программа печатает `T1`/`T2` с
точностью до сотых секунды, поэтому короткие тесты часто дают 0.00. Скрипт
сохраняет эту точность; стандартный набор содержит более крупные матрицы.

Подробные команды, stdout, stderr, статусы и матрицы каждого запуска
сохраняются в `task_3/build/test-runs/run.*/`. В каталогах есть `cases.tsv`
с параметрами всех тестов и `times.tsv` с полученными значениями.

## Состав тестов и проверка правильности

Стандартный набор покрывает четыре формулы `s=1..4`, минимальные размеры,
один блок, `m=1`, `m>n`, деление на блоки с остатком, ограничения вывода,
существующие файлы и детерминированно создаваемые матрицы:

- диагональные, треугольные, симметричные и несимметричные;
- перестановки строк/столбцов и выбор ведущего блока;
- сильно различающиеся масштабы;
- нулевые, вырожденные, почти зависимые и плохо обусловленные;
- неполные файлы, лишние числа, NaN/Inf, отсутствующие файлы и неверные аргументы.

Для каждого теста задано ожидание: решение, отказ решателя, ошибка ввода
или любой из исходов «решение/отказ» для случаев, зависящих от численной
обусловленности и применимости блочного метода. Например, обратимая матрица
может не иметь обратимого выровненного блока заданного размера.

При ожидаемом решении, кроме матриц Гильберта (`s=4`), проверяются
`Res1 <= 1e-8` и `Res2 <= 1e-6`. Если программа сообщает решение с большей
невязкой, тест помечается `FAIL`, а сообщённые времена остаются в CSV;
причина сохраняется в его логе. Для `s=4` общий допуск не применяется:
невязки остаются в логах для оценки точности, а NaN, бесконечности,
аварийное завершение и несоответствие ожидаемому исходу по-прежнему
считаются ошибками теста. Ожидаемые отказы и ошибки ввода записывают
`-1`, но сами проверки считаются успешными.

Код завершения скрипта: 0 — все ожидания выполнены; 1 — есть `FAIL`,
но строка результатов сохранена; 2 — ошибка запуска или файла результатов.
Строка добавляется после прохождения всего набора; прерывание пользователем
или ошибка сборки не создают незавершённую строку.

## Отображение результатов

Таблица без дополнительных библиотек:

```bash
python3 task_3/plot_results.py --table
python3 task_3/plot_results.py --table --case formula_s1 --last 3
```

Для графика нужен `matplotlib`, устанавливаемый в выбранное окружение Python:

```bash
python3 -m pip install matplotlib
python3 task_3/plot_results.py
python3 task_3/plot_results.py task_3/results_full_4000_m1_2000.csv --case benchmark --last 3
python3 task_3/plot_results.py task_3/results_full_4000_m1_2000.csv --table --case n4000 --case n2000
python3 task_3/plot_results.py --metric T2 --case file --save task_3/timings.png
```

Одна линия соответствует одному запуску. `--case` выбирает подстроку имени
или шаблон, например `'benchmark_formula_s1_*'`; параметр можно повторять.
`--last N` ограничивает историю последними N запусками. `--metric T1|T2`
выбирает показатель, по умолчанию T1. `--save` сохраняет PNG/SVG/PDF без
открытия окна. Красный крест у нуля обозначает `-1` хотя бы в одном выбранном
запуске, пустой кружок — успешное время 0. Точные значения каждого запуска
можно посмотреть через `--table`.
Таблица и сводка показывают систему каждого запуска; подписи линий на
графике содержат ОС и архитектуру. Старые CSV тоже можно отображать.

## Проверка самих скриптов

```bash
python3 -B -m unittest discover -s task_3/tests -p 'test_*.py' -v
```

Проверяется чтение именно финального времени, успешный ноль, отказ при коде
завершения 0, повреждённый отчёт, ожидание завершения процесса без тайм-аута,
пути с пробелами, добавление строк без перезаписи, защита от смены заголовка
и чтение данных для отображения.

Для обычного запуска тестов достаточно `bash task_3/test.sh`.
