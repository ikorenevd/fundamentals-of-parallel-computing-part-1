# Сравнение вычисления нормы матрицы

Запуск из корня репозитория:

```sh
make -C task_2 benchmark
```

Сравниваются три варианта одной нормы `max_j sum_i |A[i,j]|`:

1. `baseline`: исходный обход по глобальным столбцам с вычислением адреса
   каждого элемента в блочном массиве.
2. `block_columns`: обход по блочным столбцам; суммы накапливаются в буфере
   длины фактической ширины блока (не более m).
3. `storage_order`: используемая программой функция `calculate_matrix_norm`
   из `solver.cpp`. Блоки читаются в порядке хранения, суммы накапливаются
   в рабочем векторе длины n. При m=1 используется обычный построчный обход.

Выбран третий вариант: последовательное чтение всей матрицы и хорошие
результаты при малых блоках. Второй вариант иногда немного быстрее при
больших блоках; универсального победителя для любого оборудования нет.
Дополнительный вектор выделяется в `LinearSystem::memory_alloc()`, не внутри
решателя. Общий объём массивов — n²+3n элементов double.
Порядок сложения элементов каждого столбца сохраняется.

Методика: матрица заполняется заранее знакопеременными целыми значениями,
выделение памяти и заполнение не входят в замер. Каждый вариант прогревается,
затем выполняется 7 раз с чередованием порядка вариантов; ниже медианы в мс.
Все результаты сверяются с исходным алгоритмом. На Linux процесс привязан
к последнему доступному логическому процессору. n=2051 и m=90 дополнительно
покрывают неполные блоки. Измеряется только норма, не вся программа и не
будущий метод Гаусса. Значения зависят от частоты CPU, кэша и фоновой нагрузки.

Результаты 2026-10-02: Intel Core i5-1135G7, Linux x86-64,
g++ 16.2.1, флаги проекта (`-O3 -mfpmath=sse`, без `-ffast-math`).
Повторный запуск выполнен без параллельного запуска тестов/сборки.
